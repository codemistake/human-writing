**EN:** A Russian-first [Agent Skill](https://agentskills.io) that makes agent prose read like competent human writing instead of default LLM output. It strips bureaucratic Russian, chatbot habits and templated rhetoric while preserving meaning. It is a synthesis of three MIT projects, not a concatenation, and it does not try to fool AI detectors. English rules are included as a secondary branch.

---

## Что это

`human-writing` — writing skill для AI-агентов. Он меняет не содержание ответа, а то, как агент разговаривает с человеком.

Особенно полезен для coding agents, которые отвечают технически правильно, но примерно так:

> Стоит отметить, что данный подход представляет собой достаточно эффективное решение, которое позволяет существенно повысить качество взаимодействия...

вместо:

> Этот вариант проще и в твоём случае подходит лучше.

## Зачем это нужно

У современных моделей узнаваемая манера общения. Они любят:

- пересказывать вопрос перед ответом;
- начинать с «Отличный вопрос»;
- писать «Важно отметить...» там, где отмечать нечего;
- превращать два предложения в статью с шестью разделами;
- использовать канцелярит вместо нормальных слов;
- строить конструкции «это не просто X — это Y»;
- повторять один вывод несколько раз разными словами;
- заканчивать каждый ответ предложением дальнейшей помощи;
- переносить английские LLM-паттерны в русский текст.

По отдельности это мелочи. Вместе они дают текст, который читаешь и сразу понимаешь: «это написал AI».

Цель скилла не в обходе AI-детекторов. Она проще: сделать общение агента с человеком менее раздражающим и более естественным.

## Что делает скилл

Скилл работает не со списком «плохих слов», а с несколькими слоями сразу. Примеры ниже иллюстративные; реальный прогон — в разделе «До / после».

**Убирает chatbot-поведение.** «Отличный вопрос! Давайте разберёмся.» становится «Да. Здесь проблема в...». «Если хотите, я также могу помочь вам настроить...» исчезает, если предложение не нужно.

**Чистит русский канцелярит.**

```text
Необходимо осуществить настройку параметров конфигурации.
→ Нужно настроить конфигурацию.

Данное решение позволяет осуществить оптимизацию процесса обработки запросов.
→ Это ускоряет обработку запросов.
```

**Убирает типичные AI-конструкции.** «Это не просто инструмент — это фундаментально новый подход к разработке» без реального контраста превращается в «Это другой подход к разработке». Под наблюдением также «Стоит отметить...», «Важно понимать...», «Следует учитывать...», «Давайте погрузимся...», «Не только X, но и Y», искусственные тройки аргументов и псевдоаналитические выводы без новой информации.

**Не превращает каждый ответ в статью.** На вопрос «Redis здесь нужен?» агенту не обязательно отвечать разделами «Введение / Преимущества / Недостатки / Итог». Нормальный ответ:

```text
Скорее нет.

Если Redis нужен только ради кеша этого запроса, я бы сначала оставил
локальный кеш. Redis имеет смысл добавлять, когда кеш должен быть общим
между несколькими инстансами.
```

**Сохраняет технический язык.** `endpoint`, `deploy`, `rollback`, `middleware`, `race condition`, `feature flag` остаются как есть. Скилл не заменяет нормальную разработческую речь литературным русским ради «чистоты языка».

**Не запрещает нормальную русскую пунктуацию.** Некоторые humanizer-промпты работают механикой: `NEVER use em dash`, `NEVER write sentences longer than N words`. Длинное тире для русского нормально. Проблема появляется, когда модель двадцать раз подряд пишет «Это не X — это Y». Скилл правит паттерн, а не знак препинания.

## Russian-first

Русский здесь не перевод английских правил. У русского AI-текста свои признаки:

- «Стоит отметить...», «Следует подчеркнуть...», «В рамках данного подхода...», «Осуществление оптимизации...»;
- избыток отглагольных существительных;
- чрезмерно официальный регистр;
- английский синтаксис, перенесённый в русский;
- попытка придать каждому предложению «вес»;
- ненужные связки между очевидно связанными мыслями.

Скилл учитывает именно их. Для английского текста внутри есть отдельная ветка правил.

## Как устроено

```text
human-writing/
├── SKILL.md                 # полные правила, загружаются по требованию
├── GLOBAL_RULES.md          # короткий блок для AGENTS.md / CLAUDE.md
├── install.sh / install.ps1
├── SOURCES.md
├── THIRD_PARTY_LICENSES.md
└── LICENSE
```

**`GLOBAL_RULES.md`** (~280 слов) держится включённым постоянно. Он отвечает за базовое поведение: отвечать сразу, не пересказывать запрос, не хвалить пользователя автоматически, не раздувать короткий ответ, не заканчивать каждое сообщение стандартным chatbot CTA. Подходит для `AGENTS.md`, `CLAUDE.md`, глобальных инструкций и system prompt.

**`SKILL.md`** — полная версия. Подключается, когда агент пишет или редактирует текст для людей: документацию, README, сообщения пользователю, письма, release notes, описания задач, статьи, посты, product copy. Внутри: режимы «ответ / черновик / редактура / аудит / точечная правка», базовый стиль для русского, шаблонная риторика LLM, ритм и структура, голос автора, жанровая поправка, английская ветка, финальная проверка.

Приоритеты внутри скилла фиксированы: факты и требования среды → явные инструкции пользователя → жанр и аудитория → правила стиля.

### Рекомендуемая конфигурация

Для coding agent не стоит включать полный humanizer на каждый ответ. Ответ «panic происходит из-за записи в nil map» не нужно «очеловечивать», он уже хороший. Поэтому:

- `GLOBAL_RULES.md` — всегда активен, правит обычные ответы;
- `SKILL.md` — подключается там, где модель начинает писать текст, а не просто передавать информацию.

## Установка

### Через Skills CLI (любой агент)

```bash
npx skills add codemistake/human-writing --global
```

Без `--global` скилл ставится только в текущий проект. `--agent claude-code`, `--agent codex`, `--agent '*'` выбирают агентов.

### Вручную

Скопируйте папку репозитория в каталог скиллов агента:

| Агент | Путь |
|---|---|
| Claude Code | `~/.claude/skills/human-writing/` |
| Codex | `~/.codex/skills/human-writing/` |
| Cursor | `~/.cursor/skills/human-writing/` |
| OpenCode | `~/.config/opencode/skills/human-writing/` |

Или скриптом из клона репозитория:

```bash
./install.sh claude      # opencode | claude | codex | cursor | all
```

```powershell
.\install.ps1 claude
```

Если платформа не поддерживает skills как отдельную сущность, содержимое `SKILL.md` можно подать как дополнительный system/developer prompt, а `GLOBAL_RULES.md` — как постоянные инструкции агента.

### Claude.ai / Claude Desktop

Скачайте `human-writing.zip` со страницы [Releases](https://github.com/codemistake/human-writing/releases/latest) и загрузите его в **Settings → Capabilities → Skills → Upload skill**. Не берите архив всего репозитория: загрузчику нужен `SKILL.md` в корне архива.

### Второй слой: глобальные правила

Добавьте содержимое [GLOBAL_RULES.md](./GLOBAL_RULES.md) в свой глобальный `AGENTS.md` / `CLAUDE.md` / инструкции OpenCode. Установочные скрипты этот файл специально не трогают, чтобы не затереть ваши правила.

## Что скилл намеренно не делает

- **Не обманывает AI-детекторы.** Детекторы ненадёжны, а оптимизация под detector score обычно делает текст хуже. Критерий другой: было бы нормально получить такой текст от реального коллеги?
- **Не добавляет искусственные ошибки.** Никаких специальных опечаток, сленга, обрывков предложений и случайных разговорных частиц. Человеческий текст не обязан быть плохим текстом.
- **Не делает текст «максимально разговорным».** У README, RFC, сообщения в Telegram и ответа на code review разный стиль. Скилл сохраняет подходящий регистр, а не приводит всё к одному голосу.
- **Не заменяет содержание.** Если модель галлюцинирует факты, writing skill это не исправит. Он отвечает за «как сказать», а не за «правда ли это».

## Бенчмарк

Скилл проверен на 60 русских входах семи типов: утрированный канцелярит, грамотный текст с LLM-паттернами, длинные документы, написание по данным, голос автора, названный адресат и контрольные тексты, которые трогать нельзя. Та же модель без скилла и со скиллом, одинаковые запросы, слепая парная оценка судьёй. Тексты писали **Claude Sonnet 5** и **Claude Haiku 4.5**, судил **Claude Opus 5** — модель сильнее обеих и не участвовавшая в написании. Обход AI-детекторов не измерялся, потому что это не цель.

Как читать: baseline — та же модель без каких-либо правил. Скилл полезен, только если побеждает baseline чаще, чем проигрывает, и при этом не теряет и не выдумывает факты.

| 60 входов, v1.3.1 | Sonnet 5: baseline / skill | Opus 5: baseline / skill |
|---|---|---|
| Судья предпочёл | 26 / **30** (4 ничьи) | 22 / **28** (10 ничьих) |
| Фактов потеряно | 31 / **17** | 30 / **11** |
| Фактов выдумано | 26 / **14** | 38 / **2** |
| Контрольные тексты изменены | 1 из 3 / **0 из 3** | 0 из 3 / 0 из 3 |

Прогон на Opus 5 сделан на версии v1.3.0; правила между ней и v1.3.1 менялись только в части списков и жанра поста.

**Главный результат — не счёт побед, а факты.** На Opus 5 базовая модель выдумала 38 утверждений на 60 текстов, со скиллом — 2. Чем сильнее модель, тем точнее она исполняет правило «каждое утверждение должно быть в исходнике». Где скилл помогает больше всего: названный адресат (8:2 на Sonnet) и грамотный текст с LLM-паттернами, где модель без правил вырезает вместе с паттернами содержание (20 потерянных фактов против 11). Где слабее: редактура утрированного канцелярита (6:10) — трассировка делает правку осторожнее.

**Счёт побед на Sonnet 5 шумит сильнее, чем разница между версиями скилла.** На исходных 50 входах пять прогонов дали скиллу 21–24 победы при 16–24 у baseline: разброс перекрывает любую разницу между близкими версиями правил. Поэтому сравнивать версии по счёту нельзя, и опорные числа здесь — фактические, а не победные. Результат зависит и от модели: каждая таблица подписана той, что писала тексты.

Первая строка — базовая модель без правил, то есть то, что получает пользователь без всякого humanizer. Счёта побед у неё нет, она точка отсчёта, но факты она теряет: 18 на 50 текстов в среднем, разброс 12–26 по шести прогонам одного и того же набора разными судьями.

Пока скилл просто установлен, он стоит только своего описания: у нашего это около 140 токенов на каждый запрос. Тело грузится при срабатывании и живёт в контексте до конца сессии. Оценка по токенизатору `o200k_base` с поправкой на Claude, подробности — в [bench/](./bench/).

Ни один не обыграл базовую модель. Наша строка здесь — те же 50 входов из прогона v1.3.1, без десяти входов с названным адресатом, которых у конкурентов нет; на полном наборе из 60 счёт 30 / 26 / 4. Ближе всех comol, но он и вмешивается меньше всех: почти не трогает текст, поэтому теряет мало и выигрывает редко. У остальных другая цель: большинство оптимизируют текст под AI-детекторы, а правила «добавь мнение, сломай ритм, оживи» стоят фактов. Бенчмарк написан автором одного из участников, поэтому входы, тексты и вердикты опубликованы целиком.

Метод, входы, все тексты, вердикты судьи с комментариями и разбивка по типам — в [bench/](./bench/).

## Ограничения

Это промпт-уровень. Он убирает самые частые дефолты модели, но не отменяет их полностью. На длинном тексте полезно попросить агента сделать аудит по разделу 12 скилла и переписать по его результатам. На уже нормальном тексте скилл должен ничего не трогать, и это тоже правило.

## Принцип проекта

Цель не в том, чтобы сделать AI «неотличимым от человека». Цель — убрать из текста то, что модель добавила только потому, что она модель. Если предложение ничего не добавляет, его можно удалить. Если мысль можно сказать проще, её стоит сказать проще. Если ответ закончен, не нужно ещё одного абзаца с тем же выводом.

- [ilyautov/humanizer-ru](https://github.com/ilyautov/humanizer-ru) — русскоязычные AI-паттерны и антиканцелярит;
- [blader/humanizer](https://github.com/blader/humanizer) — база англоязычных LLM writing patterns.

Правила пересмотрены, дедуплицированы и адаптированы под coding agents, а не склеены из исходных промптов. Что именно взято — в [SOURCES.md](./SOURCES.md), тексты лицензий — в [THIRD_PARTY_LICENSES.md](./THIRD_PARTY_LICENSES.md).
