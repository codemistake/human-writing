Идемпотентность — фундаментальное свойство операции: её повторное выполнение даёт тот же результат, что и однократное.

Пример: клиент отправил запрос и не получил ответ из-за сетевой ошибки. Повторить запрос? А если первый всё-таки выполнился на сервере? Тут и нужна идемпотентность.

В HTTP метод `PUT` идемпотентен: сколько раз ни отправь один и тот же `PUT`, состояние ресурса будет одинаковым. А `POST` — нет: каждый `POST` может создать новую сущность.

Чтобы сделать `POST` безопасным для повторов, используют заголовок `Idempotency-Key`. Клиент генерирует уникальный ключ, сервер запоминает результат и при повторе с тем же ключом возвращает сохранённый ответ, а не выполняет операцию заново.

Идемпотентность позволяет безопасно повторять запросы, защищает от дублирования данных и делает систему надёжнее. Это необходимость для любого API, работающего в реальном мире, а не просто хорошая практика.
