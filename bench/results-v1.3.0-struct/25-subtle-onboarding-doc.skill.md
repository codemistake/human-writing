Код-ревью — часть нашей инженерной культуры.

У нас две основные ветки: `main` и `develop`. В `main` попадает только протестированный код из `develop`.

Каждый pull request должен получить два одобрения, и хотя бы одно — от владельца кода из `CODEOWNERS`.

При слиянии используем squash: история остаётся чистой и понятной.

Не бойтесь задавать вопросы. Лучше спросить, чем сломать.
