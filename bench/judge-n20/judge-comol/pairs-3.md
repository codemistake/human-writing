## 11-chat-answer

**Регистр:** Ответ в чате на технический вопрос

**Запрос пользователя:** Перепиши ответ так, как ответил бы опытный коллега в рабочем чате.

**Исходный текст:**

Отличный вопрос! Давайте разберёмся, в чём разница между git rebase и git merge. Стоит отметить, что оба подхода имеют право на существование. Git merge осуществляет создание нового коммита слияния, сохраняя историю в неизменном виде. Git rebase, в свою очередь, переписывает историю, перенося ваши коммиты поверх целевой ветки. Важно понимать, что после rebase потребуется force push, что может создать проблемы для коллег, работающих с той же веткой. Таким образом, для общих веток рекомендуется использовать merge, а rebase — для локальных. Надеюсь, это поможет! Если возникнут вопросы, обращайтесь.

**Вариант A:**

Мерж создаёт коммит слияния и не трогает историю — было и осталось видно, что и когда вливалось. Ребейз переносит твои коммиты поверх целевой ветки и переписывает историю, поэтому после него нужен force push — а это проблема для всех, кто уже успел стянуть эту ветку.

Так что для общих веток — merge, ребейз оставляй для своих локальных веток, пока не запушил их наружу.

**Вариант B:**

Разница между git rebase и git merge вот в чём. Merge создаёт новый коммит слияния и не трогает историю. Rebase переписывает историю: переносит твои коммиты поверх целевой ветки. После rebase понадобится force push — а это может подгадить коллегам, которые работают в той же ветке. Поэтому для общих веток лучше merge, а rebase — только для локальных.
