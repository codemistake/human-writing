**Идемпотентность** — это свойство операции, при котором её повторное выполнение даёт тот же результат, что и однократное.

Представьте ситуацию: клиент отправил запрос, но не получил ответ из-за сетевой ошибки. Что делать? Повторить запрос? Но что, если первый запрос всё-таки выполнился? Вот где идемпотентность становится важна.

В HTTP метод PUT идемпотентен: сколько бы раз вы ни отправили один и тот же PUT, состояние ресурса будет одинаковым. POST — нет: каждый POST может создавать новую сущность.

Чтобы сделать POST безопасным для повторов, используют заголовок Idempotency-Key. Клиент генерирует уникальный ключ, сервер запоминает результат и при повторе с тем же ключом возвращает сохранённый ответ, а не выполняет операцию заново.

**Итог:** идемпотентность позволяет безопасно повторять запросы, защищает от дублирования данных и делает систему надёжнее. Это необходимость для любого API, работающего в реальном мире.
