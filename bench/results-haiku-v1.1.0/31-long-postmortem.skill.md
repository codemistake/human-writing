# Постмортем: недоступность публичного API 3 сентября

## Краткое описание

3 сентября в период с 11:47 до 13:20 публичный API был полностью недоступен для всех клиентов. Инцидент длился 93 минуты и был вызван истечением срока действия TLS-сертификата на ingress-контроллере. Сертификат не был своевременно перевыпущен из-за сбоя в cert-manager.

## Хронология

11:47 — система мониторинга Prometheus зафиксировала рост ошибок TLS handshake до 100%. Алерт не был отправлен, так как правило алертинга для этой метрики отсутствовало.

11:52 — служба поддержки начала получать жалобы от клиентов.

12:05 — сотрудник поддержки вручную уведомил дежурного инженера через PagerDuty.

12:10 — дежурный инженер начал диагностику.

12:35 — установлено, что сертификат истёк в 11:47.

12:40 — попытка ручного перевыпуска сертификата через cert-manager не удалась: pod находился в CrashLoopBackOff с 28 августа из-за некорректной конфигурации CRD после планового апгрейда кластера.

12:55 — cert-manager перезапущен с исправленной конфигурацией.

13:12 — сертификат успешно перевыпущен через Let's Encrypt.

13:20 — API полностью восстановлен.

## Причины

**Непосредственная:** TLS-сертификат с периодом действия 90 дней истёк. Он должен был перевыпуститься за 30 дней до истечения.

**Корневая:** cert-manager был в CrashLoopBackOff с 28 августа (7 дней) из-за ошибки в обновлении CRD при апгрейде кластера. Автоматический перевыпуск не работал.

**Способствующие факторы:** отсутствовали алерты на истечение сертификата и на состояние подов cert-manager.

## Влияние

В течение 93 минут был недоступен публичный API для всех клиентов, что затронуло около 12% дневного объёма запросов. Мобильные приложения отображали ошибку соединения.

## Положительное

Сотрудник поддержки проявил инициативу и вручную эскалировал проблему дежурному, что сократило время реакции.

## Что улучшить

1. Добавить алерт в Prometheus на истечение сертификата менее чем через 14 дней.
2. Добавить алерт на поды в состоянии CrashLoopBackOff в namespace cert-manager.
3. Включить проверку состояния cert-manager в чеклист планового апгрейда кластера.
4. Провести аудит всех автоматических процессов, отсутствие которых не вызывает алертов.
