# Постмортем: недоступность публичного API 3 сентября

## Краткое описание

3 сентября с 11:47 до 13:20 публичный API был полностью недоступен для всех клиентов. Инцидент длился 93 минуты. Причина: истечение срока действия TLS-сертификата на ingress-контроллере, которое не было обнаружено из-за сбоя в cert-manager.

## Хронология

11:47 — Prometheus зафиксировал 100% ошибок TLS handshake. Алерт не поступил, так как правило алертинга не существовало.

11:52 — Служба поддержки начала получать обращения от клиентов.

12:05 — Дежурный инженер был уведомлён вручную сотрудником поддержки.

12:10–12:35 — Диагностика. Выявлено, что сертификат истёк в 11:47.

12:40 — Попытка ручного перевыпуска через cert-manager не удалась: подсистема была в CrashLoopBackOff с 28 августа.

12:55 — Cert-manager перезагружен с исправленной конфигурацией.

13:12 — Сертификат успешно перевыпущен через Let's Encrypt.

13:20 — API восстановлен.

## Причины

Непосредственная: истечение срока действия сертификата (период действия 90 дней, перевыпуск должен происходить за 30 дней до истечения).

Корневая: cert-manager перезагружался в цикле с 28 августа из-за некорректного обновления CRD при плановом апгрейде кластера. Автоматический перевыпуск не работал в течение 7 дней.

Способствующая: отсутствие алертов на срок истечения сертификата и состояние подов cert-manager.

## Влияние

В течение 93 минут API был недоступен для 100% клиентов. Затронуто порядка 12% дневного объёма запросов. Мобильные приложения отображали ошибку соединения.

## Что было сделано хорошо

Сотрудник поддержки самостоятельно эскалировал проблему дежурному инженеру, что сократило время реакции.

## Что необходимо улучшить

1. Добавить алерт в Prometheus на истечение сертификата менее чем через 14 дней.
2. Добавить алерт на поды в состоянии CrashLoopBackOff в namespace cert-manager.
3. Включить проверку состояния cert-manager в чеклист планового апгрейда кластера.
4. Провести аудит всех автоматических процессов, отсутствие которых не вызывает алертов.
