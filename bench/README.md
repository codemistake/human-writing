# Бенчмарк

Проверяет одно: делает ли скилл текст лучше для читателя, чем та же модель без скилла, и не платит ли за это фактами. Обход AI-детекторов не измеряется, потому что не является целью скилла.

## Как читать таблицы

- **baseline** — та же модель без каких-либо правил стиля. Скилл полезен, только если побеждает baseline чаще, чем проигрывает.
- **Побед / поражений / ничьих** — вердикты слепого судьи по парам «baseline против скилла». Хорошо, когда первое число больше второго.
- **Фактов потеряно** и **фактов выдумано** — по подсчёту судьи. Хорошо: ноль.

## Метод

- **50 русских входов** ([inputs.json](./inputs.json)), шесть типов:
  - `rewrite` (17) — утрированный канцелярит в разных регистрах: рассылка, постмортем, README, поддержка, пост, аннотация, release notes, письмо, вакансия, онбординг, чат, документация, лендинг, отчёт, задача, статус, сопроводительное;
  - `subtle` (10) — грамотный текст без канцелярита, но с LLM-паттернами: тройки, «не X, а Y», симметричные абзацы, жирные мини-заголовки, вывод-пересказ, риторические вопросы, «в мире, где…»;
  - `long` (8) — тексты на 230–400 слов: постмортем, страница документации, инженерная статья, отчёт совету директоров, RFC, руководство для клиентов, положение о дежурствах, статус заказчику;
  - `generate` (8) — не редактура, а написание по данным: ответ в чате, release notes из списка, объявление, ответ на жалобу, вводная README, разбор логов, вакансия, описание PR;
  - `voice` (4) — образец текста автора плюс задание; проверяется, что голос сохранён, а факты об авторе из образца не перенесены;
  - `control` (3) — уже хорошие тексты (чат, технический ответ, пункт договора), которые трогать нельзя.
- **Условия**: одна модель, одинаковые запросы. `baseline` без правил; `skill` с прочитанным `SKILL.md`; конкуренты — с их `SKILL.md` из [competitors/](./competitors/) (снимки с SHA коммита, только текстовые правила, без их скриптов).
- **Модели**: Claude Sonnet (основной прогон) и Claude Haiku (проверка, зависит ли результат от силы модели).
- **Метрики** ([score.py](./score.py)): доля сохранённых фактов-якорей, плотность канцелярских и chatbot-маркеров на 100 слов, отношение длины, похожесть контрольных текстов на исходник.
- **Слепая парная оценка** ([judge.py](./judge.py)): судья (Claude Opus) получает исходник или исходные данные, запрос и два варианта в случайном порядке. Выбирает лучший для регистра, перечисляет потерянные и выдуманные факты, объясняет вердикт.

Запуск: результаты кладутся в `results/<id>.<условие>.md` (для Haiku — `results-haiku/`), затем

```bash
python bench/score.py                                  # BENCH_RESULTS_DIR=results-haiku для Haiku
BENCH_COND=<условие> BENCH_PER_FILE=10 python bench/judge.py make <seed>   # пары для судьи + key.json
BENCH_COND=<условие> python bench/judge.py report      # после записи judge-<условие>/verdicts-*.json
```

## Что показал расширенный набор

**На первых 20 входах baseline выигрывал не потому, что скилл плох, а потому, что задача была лёгкой.** Утрированный канцелярит Sonnet чистит и без правил. На 20 входах скилл выигрывал 8:6, при повторной оценке тех же пар другим судьёй — 10:4. Разница в две-три пары на таком объёме — шум.

**Разница появляется там, где текст выглядит грамотным.** На `subtle`-входах baseline Sonnet, убирая LLM-паттерны, вырезает и содержание: судья насчитал 17 потерянных фактов на 10 текстов. Со скиллом — 2, и счёт 8:1. Это главный результат: правило «режь воду, а не содержание» работает именно на текстах, где вода не бросается в глаза.

**Скилл держит факты на любом типе входов.** На Sonnet: 6 потерянных против 25, 3 выдуманных против 9. Контрольные тексты не тронуты.

**Слабые места v1.1.0.** Длинные тексты (2:5): судья отмечает дубли определений, висящие ссылки на вырезанный абзац, уход от «мы» в безличные формы, съезд нормативного регистра в разговорный. Голос автора (1:3): утяжелённые связки, потерянная причина, выдуманный путь в меню. Оба направления — на следующую версию.

**Слабая модель.** На Haiku скилл помогает там, где модель пишет с нуля (`generate` 7:1, `voice` 3:0), и мешает на редактуре утрированного канцелярита (`rewrite` 5:12): Haiku со скиллом выдумывает больше, чем без него. Итог 23:22 — паритет. Правила промпт-уровня не заменяют силу модели, а на слабой модели длинная инструкция сама становится источником ошибок.

**Почему они проигрывают.** Четыре из пяти в описании целятся в AI-детекторы: perplexity, burstiness, «фингерпринты ChatGPT». Правила «добавь мнение», «сломай ровный ритм», «оживи» стоят фактов: ilyautov выдумал 21 деталь на 50 текстов. Этот бенчмарк меряет другое — качество для читателя и сохранность фактов. Под свою цель они, возможно, работают; под эту — нет.

## Ограничения

- Судья и переписчик — модели одного вендора. Судья другой модели (Opus) и ослеплён, но это не оценка людьми.
- Один прогон на условие. Повторная оценка тех же 20 пар дала 10:4 вместо 8:6: две-три пары — шум. На 50 входах отрыв 26:15 и 6 против 25 потерянных фактов уже за пределами шума.
- Входы написаны для бенчмарка, а не взяты из реальной переписки.
- Метрика маркеров — regex-список, а не понимание текста; на этом наборе она никого не различает.
- Конкуренты сравнивались с baseline, а не друг с другом, и без их вспомогательных скриптов. Бенчмарк написан автором одного из участников; входы, тексты и вердикты опубликованы целиком, чтобы это можно было проверить и оспорить.
