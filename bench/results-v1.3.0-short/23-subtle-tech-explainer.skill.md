Идемпотентность — фундаментальное свойство операции: при повторном выполнении она даёт тот же результат, что и при первом.

Типичная ситуация: клиент отправил запрос и не получил ответ из-за сетевой ошибки. Повторный запрос рискует задвоить результат, если первый всё-таки выполнился, — здесь и нужна идемпотентность.

В HTTP метод PUT идемпотентен: сколько раз ни отправь один и тот же PUT, состояние ресурса останется одинаковым. POST — нет, каждый POST может создавать новую сущность.

Чтобы сделать POST безопасным для повторов, используют заголовок Idempotency-Key. Клиент генерирует уникальный ключ, сервер запоминает результат и при повторе с тем же ключом возвращает сохранённый ответ, а не выполняет операцию заново.

Идемпотентность позволяет безопасно повторять запросы, защищает от дублирования данных и делает систему надёжнее — это стандартная практика для любого API, работающего в реальном мире.
