# Постмортем: недоступность публичного API 3 сентября

## Краткое описание

3 сентября с 11:47 до 13:20 публичный API был полностью недоступен для всех клиентов. Инцидент длился 93 минуты. Причина: истёк срок действия TLS-сертификата на ingress-контроллере, и cert-manager не смог его обновить автоматически.

## Хронология

11:47 — Prometheus зафиксировал рост ошибок TLS handshake до 100%. Алерт не был отправлен: правила алертинга для этой метрики не было.

11:52 — Служба поддержки начала получать жалобы от клиентов.

12:05 — Дежурный инженер был вручную уведомлён сотрудником поддержки.

12:10 — Начата диагностика.

12:35 — Выявлено истечение сертификата в 11:47.

12:40 — Попытка ручного перевыпуска сертификата не удалась: cert-manager был в состоянии CrashLoopBackOff с 28 августа.

12:55 — cert-manager перезапущен с исправленной конфигурацией.

13:12 — Сертификат успешно перевыпущен через Let's Encrypt.

13:20 — API восстановлен.

## Причины

**Непосредственная причина:** сертификат истёк. Он выпускается на 90 дней и должен обновляться за 30 дней до истечения.

**Корневая причина:** cert-manager перезагружался в цикле с 28 августа из-за некорректного обновления CRD при плановом апгрейде кластера. Автоматический перевыпуск не работал 7 дней.

**Дополнительный фактор:** отсутствие алертов на истечение сертификата и на состояние подов cert-manager.

## Влияние

93 минуты полной недоступности API для 100% клиентов. По оценкам, затронули ~12% дневного объёма запросов. Мобильные приложения показывали ошибку соединения.

## Что было хорошо

Сотрудник поддержки проявил инициативу и эскалировал проблему дежурному инженеру, что сократило время реакции.

## Что нужно улучшить

1. Добавить алерт в Prometheus на истечение сертификата менее чем через 14 дней.
2. Добавить алерт на поды в состоянии CrashLoopBackOff в namespace cert-manager.
3. Включить проверку состояния cert-manager в чеклист планового апгрейда кластера.
4. Провести аудит всех автоматических процессов, которые не вызывают алертов при отказе.
