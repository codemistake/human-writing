# Постмортем: недоступность публичного API 3 сентября

## Краткое описание

3 сентября с 11:47 до 13:20 публичный API был полностью недоступен для всех клиентов — 93 минуты простоя. Причина: истёк срок действия TLS-сертификата на ingress-контроллере, а cert-manager был в состоянии CrashLoopBackOff.

## Хронология

11:47 — Prometheus зафиксировал 100% ошибок TLS handshake. Алерт не был отправлен, так как правила алертинга для этой метрики не существовало.

11:52 — Поддержка получила первые обращения от клиентов.

12:05 — Дежурный инженер был уведомлён вручную из поддержки.

12:10 — Начало диагностики.

12:35 — Установлено, что сертификат истёк в 11:47.

12:40 — Попытка перевыпустить сертификат через cert-manager потерпела неудачу: подсистема была в CrashLoopBackOff с 28 августа из-за ошибки в обновлённой конфигурации CRD.

12:55 — cert-manager перезапущен с исправлением.

13:12 — Сертификат успешно перевыпущен через Let's Encrypt.

13:20 — API восстановлен.

## Причины

Непосредственная причина: сертификат с периодом действия 90 дней истёк, вместо того чтобы быть перевыпущенным за 30 дней.

Корневая причина: при плановом апгрейде кластера было некорректно обновлено CRD, в результате cert-manager перезапускался в цикле с 28 августа. Автоматический перевыпуск не работал 7 дней.

Способствующий фактор: отсутствие алертов на истечение сертификата и на состояние подов cert-manager.

## Влияние

100% клиентов были отключены в течение 93 минут. Это затронуло около 12% дневного объёма запросов. Мобильные приложения отображали ошибку соединения.

## Что было хорошо

Сотрудник поддержки проявил инициативу и эскалировал проблему дежурному инженеру, сократив время реакции.

## Что нужно улучшить

1. Добавить алерт на истечение сертификата менее чем через 14 дней.
2. Добавить алерт на поды в состоянии CrashLoopBackOff в namespace cert-manager.
3. Включить проверку состояния cert-manager в чеклист планового апгрейда кластера.
4. Провести аудит всех автоматических процессов, отсутствие которых не вызывает алертов.
