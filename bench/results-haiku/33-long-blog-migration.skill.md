# Как мы переехали с Docker Compose на Kubernetes

## Почему

У нас было около 40 сервисов на трёх виртуальных машинах, управляемых Docker Compose. Год назад система работала хорошо, но потом возникли проблемы: деплой вручную по SSH, откат до получаса, масштабирование требовало ручного вмешательства. За год было два инцидента, напрямую связанных с ручным деплоем.

## Как

Миграция заняла четыре месяца, параллельно с обычной разработкой.

**Месяц 1:** инфраструктура. Описали кластер в Terraform, чтобы его можно было пересоздать одной командой.

**Месяц 2:** Helm-чарты. Столкнулись с первой проблемой: часть сервисов хранила состояние на локальном диске, их пришлось переписывать.

**Месяц 3:** ArgoCD и GitOps. Состояние кластера теперь описано в Git, деплой — это merge request.

**Месяц 4:** перевод сервисов по одному, начиная с наименее критичных.

## Результаты

- Время деплоя сократилось на 35%.
- Откат теперь занимает минуты.
- С сентября нет ни одного инцидента из-за деплоя.

## Что бы мы сделали иначе

Раньше занялись сервисами с локальным состоянием — они отняли больше всего времени.

## Выводы

Переезд на Kubernetes — это не просто смена оркестратора. Это новый подход: инфраструктура как код, деплой через Git, автоматизация вместо ручных действий. Было сложно, но окупилось.
