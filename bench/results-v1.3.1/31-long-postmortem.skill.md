# Постмортем: недоступность публичного API 3 сентября

## Краткое описание

3 сентября с 11:47 до 13:20 публичный API был полностью недоступен для всех клиентов. Инцидент продолжался 93 минуты. Причина — истечение срока действия TLS-сертификата на ingress-контроллере: сбой в cert-manager помешал вовремя это заметить.

## Хронология

В 11:47 Prometheus зафиксировал рост ошибок TLS handshake до 100%. Алерт не пришёл: правила алертинга для этой метрики не было.

В 11:52 в службу поддержки начали поступать обращения от клиентов. В 12:05 сотрудник поддержки вручную уведомил дежурного инженера через PagerDuty.

В 12:10 дежурный инженер начал диагностику и в 12:35 установил, что сертификат истёк в 11:47. В 12:40 он попытался вручную перевыпустить сертификат через cert-manager, но это не сработало: под cert-manager был в состоянии CrashLoopBackOff с 28 августа.

В 12:55 cert-manager перезапустили с исправленной конфигурацией. В 13:12 сертификат перевыпустили через Let's Encrypt. В 13:20 API полностью восстановили.

## Причины

Непосредственная причина — истечение срока действия сертификата. Он выпускается автоматически на 90 дней и должен перевыпускаться за 30 дней до истечения.

Корневая причина — cert-manager с 28 августа перезапускался по кругу из-за некорректного обновления CRD при плановом апгрейде кластера. Из-за этого автоматический перевыпуск не работал 7 дней.

Способствующий фактор — отсутствие алертов на срок истечения сертификата и на состояние подов cert-manager.

## Влияние

В течение 93 минут публичный API был недоступен для 100% клиентов. По предварительным оценкам, это затронуло около 12% дневного объёма запросов. Мобильные приложения, использующие этот API, показывали ошибку соединения.

## Что было сделано хорошо

Сотрудник поддержки проявил инициативу и сам эскалировал проблему дежурному инженеру — это сократило время реакции.

## Что необходимо улучшить

Чтобы предотвратить повторение, запланированы такие меры:

1. Добавить алерт в Prometheus на истечение сертификата менее чем через 14 дней.
2. Добавить алерт на поды в состоянии CrashLoopBackOff в namespace cert-manager.
3. Включить проверку состояния cert-manager в чеклист планового апгрейда кластера.
4. Провести аудит автоматических процессов, у которых нет алертов на сбой.
