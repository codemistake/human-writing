Код-ревью — сердце нашей инженерной культуры.

У нас две основные ветки: main и develop. В main попадает только протестированный код через develop.

Каждый pull request должен получить два одобрения. Хотя бы одно должно быть от владельца кода из файла CODEOWNERS.

Мы используем squash при слиянии — история должна оставаться чистой и понятной.

Последнее: не бойтесь задавать вопросы. Лучше спросить, чем сломать.
