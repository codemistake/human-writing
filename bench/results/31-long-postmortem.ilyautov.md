# Постмортем: недоступность публичного API 3 сентября

## Краткое описание

3 сентября с 11:47 до 13:20 публичный API был полностью недоступен для всех клиентов: 93 минуты простоя. Причина: истёк TLS-сертификат на ingress-контроллере, а cert-manager не успел его перевыпустить из-за сбоя.

## Хронология

В 11:47 Prometheus зафиксировал рост ошибок TLS handshake до 100%. Алерт не сработал: правило для этой метрики отсутствовало.

В 11:52 в поддержку пошли обращения от клиентов. В 12:05 сотрудник поддержки вручную поднял PagerDuty и вызвал дежурного инженера.

В 12:10 инженер начал диагностику. В 12:35 выяснилось: сертификат истёк ровно в 11:47. В 12:40 попытались перевыпустить его через cert-manager вручную, не вышло: под cert-manager с 28 августа сидел в CrashLoopBackOff.

В 12:55 cert-manager перезапустили с исправленной конфигурацией. В 13:12 Let's Encrypt выдал новый сертификат. В 13:20 API снова заработал.

## Причины

Непосредственная причина: истёкший сертификат. Он выпускается автоматически на 90 дней и должен перевыпускаться за 30 дней до истечения.

Корневая причина: cert-manager перезапускался в цикле с 28 августа, плановый апгрейд кластера сломал обновление CRD. Из-за этого автоматический перевыпуск не работал семь дней.

Дополнительный фактор: не было алертов ни на истечение сертификата, ни на состояние подов cert-manager.

## Влияние

93 минуты простоя для 100% клиентов, по предварительным оценкам это около 12% дневного трафика. Мобильные приложения всё это время показывали ошибку соединения.

## Что сработало хорошо

Сотрудник поддержки сам эскалировал проблему дежурному инженеру, не дожидаясь автоматического алерта, и это сократило время реакции.

## Что нужно улучшить

1. Добавить алерт в Prometheus на истечение сертификата менее чем за 14 дней.
2. Добавить алерт на CrashLoopBackOff в namespace cert-manager.
3. Включить проверку cert-manager в чеклист планового апгрейда кластера.
4. Провести аудит автоматических процессов, отсутствие алертов на которые пока никто не заметил.
