Код-ревью — часть нашего инженерного процесса.

У нас две основные ветки: main и develop. В main попадает только код, прошедший через develop и протестированный.

Каждый pull request получает два одобрения, одно из которых — от владельца кода из CODEOWNERS.

При слиянии используем squash: история остаётся чистой и понятной.

Если сомневаетесь — спрашивайте. Лучше спросить, чем сломать.
