# Постмортем: недоступность публичного API 3 сентября

## Краткое описание

3 сентября с 11:47 до 13:20 публичный API был недоступен для всех клиентов — 93 минуты. Причина: истёк TLS-сертификат на ingress-контроллере, а cert-manager не смог перевыпустить его из-за сбоя в собственной работе.

## Хронология

11:47 — Prometheus зафиксировал рост ошибок TLS handshake до 100%. Алерт не сработал: правило алертинга для этой метрики отсутствовало.

11:52 — в поддержку начали поступать обращения от клиентов.

12:05 — сотрудник поддержки вручную уведомил дежурного инженера через PagerDuty.

12:10 — дежурный инженер начал диагностику.

12:35 — выяснилось, что сертификат истёк в 11:47.

12:40 — попытка вручную перевыпустить сертификат через cert-manager не удалась: под cert-manager находился в CrashLoopBackOff с 28 августа.

12:55 — cert-manager перезапущен с исправленной конфигурацией.

13:12 — сертификат перевыпущен через Let's Encrypt.

13:20 — API полностью восстановлен.

## Причины

Непосредственная причина — истёк срок действия сертификата. Он выпускается автоматически на 90 дней и должен перевыпускаться за 30 дней до истечения.

Корневая причина — cert-manager с 28 августа перезапускался в цикле из-за некорректного обновления CRD при плановом апгрейде кластера. Поэтому автоперевыпуск не работал 7 дней.

Способствующий фактор — не было алерта ни на срок истечения сертификата, ни на состояние подов cert-manager.

## Влияние

93 минуты публичный API был недоступен для всех клиентов — это порядка 12% дневного объёма запросов. Мобильные приложения показывали ошибку соединения.

## Что было сделано хорошо

Сотрудник поддержки сам эскалировал проблему дежурному инженеру, не дожидаясь автоматического алерта, — это сократило время реакции.

## Что необходимо улучшить

1. Добавить в Prometheus алерт на истечение сертификата менее чем через 14 дней.
2. Добавить алерт на поды в CrashLoopBackOff в namespace cert-manager.
3. Включить проверку состояния cert-manager в чеклист планового апгрейда кластера.
4. Провести аудит автоматических процессов, отсутствие алертов на которые никто не отслеживает.
