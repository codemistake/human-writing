# Постмортем: недоступность публичного API 3 сентября

## Краткое описание

3 сентября с 11:47 до 13:20 публичный API был полностью недоступен для всех клиентов. Инцидент длился 93 минуты. Причина - истёк TLS-сертификат на ingress-контроллере, и это вовремя не заметили из-за сбоя cert-manager.

## Хронология

В 11:47 Prometheus зафиксировал рост ошибок TLS handshake до 100%. Алерт не пришёл: правило алертинга для этой метрики отсутствовало.

В 11:52 начали поступать обращения от клиентов. В 12:05 сотрудник поддержки вручную уведомил дежурного инженера через PagerDuty.

В 12:10 дежурный начал диагностику. В 12:35 выяснилось, что сертификат истёк в 11:47. В 12:40 попробовали перевыпустить сертификат вручную через cert-manager - не вышло, потому что под cert-manager с 28 августа находился в CrashLoopBackOff.

В 12:55 cert-manager перезапустили с исправленной конфигурацией. В 13:12 сертификат перевыпустили через Let's Encrypt. В 13:20 API полностью восстановили.

## Причины

Непосредственная причина - истёк срок действия сертификата. Он выпускается автоматически на 90 дней и должен перевыпускаться за 30 дней до истечения.

Корневая причина - cert-manager с 28 августа перезапускался в цикле из-за некорректного обновления CRD при плановом апгрейде кластера. Из-за этого автоматический перевыпуск не работал 7 дней.

Дополнительный фактор - не было алерта ни на истечение сертификата, ни на состояние подов cert-manager.

## Влияние

93 минуты публичный API был недоступен для 100% клиентов. По предварительным оценкам, это затронуло около 12% дневного объёма запросов. Мобильные приложения показывали ошибку соединения.

## Что было сделано хорошо

Сотрудник поддержки сам эскалировал проблему дежурному инженеру, не дожидаясь автоматического алерта - это сократило время реакции.

## Что нужно улучшить

1. Добавить в Prometheus алерт на истечение сертификата менее чем через 14 дней.
2. Добавить алерт на поды в CrashLoopBackOff в namespace cert-manager.
3. Включить проверку состояния cert-manager в чеклист планового апгрейда кластера.
4. Провести аудит автоматических процессов, за отсутствием которых сейчас никто не следит.
