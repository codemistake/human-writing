Идемпотентность — фундаментальное свойство операции: её повторное выполнение даёт тот же результат, что и однократное.

Пример: клиент отправил запрос и не получил ответ из-за сетевой ошибки. Повторить запрос напрямую рискованно — неизвестно, выполнился ли первый. Именно для этого нужна идемпотентность.

В HTTP метод PUT идемпотентен: сколько раз ни отправь один и тот же PUT, состояние ресурса не изменится. А вот POST — нет: каждый POST может создавать новую сущность.

Чтобы сделать POST безопасным для повторов, используют заголовок Idempotency-Key. Клиент генерирует уникальный ключ, сервер запоминает результат и при повторе с тем же ключом возвращает сохранённый ответ, а не выполняет операцию заново.

Идемпотентность позволяет безопасно повторять запросы, защищает от дублирования данных и делает систему надёжнее — для любого API, работающего в реальном мире.
