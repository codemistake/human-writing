Идемпотентность - фундаментальное свойство операции: её повторное выполнение даёт тот же результат, что и однократное.

Пример: клиент отправил запрос и не получил ответ из-за сетевой ошибки. Повторный запрос может задублировать операцию, если первый всё-таки выполнился на сервере. Идемпотентность решает именно эту проблему.

В HTTP метод PUT идемпотентен - сколько раз ни отправь один и тот же PUT, состояние ресурса будет одинаковым. POST - нет: каждый POST может создавать новую сущность.

Чтобы сделать POST безопасным для повторов, используют заголовок Idempotency-Key. Клиент генерирует уникальный ключ, сервер запоминает результат и при повторе с тем же ключом возвращает сохранённый ответ, а не выполняет операцию заново.

Идемпотентность защищает от дублирования данных при повторных запросах - это необходимость для любого API, который работает в реальном мире с сетевыми сбоями.
