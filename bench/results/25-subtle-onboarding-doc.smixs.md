Код-ревью - основа нашей инженерной культуры.

У нас две основные ветки: main и develop. В main попадает только протестированный код, и только через develop.

Каждый pull request должен получить два одобрения. Хотя бы одно - от владельца кода из файла CODEOWNERS.

При слиянии используем squash: так история остаётся чистой и понятной.

Не бойтесь задавать вопросы. Лучше спросить, чем сломать.
