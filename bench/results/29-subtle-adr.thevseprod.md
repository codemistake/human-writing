## Контекст

Наши сервисы общаются по REST. Это работало, пока сервисов было три. Сейчас их двадцать, и REST начинает показывать свои ограничения.

## Решение

Переходим на gRPC для межсервисного взаимодействия. Это фундаментальный сдвиг в том, как мы думаем о контрактах между сервисами, а не просто смена протокола. Схемы protobuf становятся единственным источником истины.

REST остаётся для внешнего API и для браузера: grpc-web добавляет сложность, которая на текущем этапе не оправдана.

## Последствия

Получаем строгие контракты, генерацию клиентов и меньший оверхед. Взамен команде придётся освоить новый инструментарий. Это инвестиция, которая окупится.
